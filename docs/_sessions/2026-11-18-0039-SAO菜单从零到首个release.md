## 1. 任务目标与当前进度

目标：做一个《刀剑神域》（SAO）风格的 macOS 快捷启动菜单，尽量还原动画里的交互，菜单内容可自定义，并开源到 GitHub。

- 图形化设置窗口（菜单树 + 表单 + 热键录制 + 系统文件选择框），修改自动保存。
- 应用图标、`app` 类型条目显示真实应用图标。
- 给 agent 用的 skill `sao-menu-config`（按用户要求修改菜单配置）及其校验脚本。

## 2. 关键决策及理由

- **架构：原生 Swift 外壳 + WKWebView 画界面**。Swift 负责透明全屏浮层、全局热键、手势、音效、执行动作；菜单和动画用 HTML/CSS/JS。理由：无任何第三方依赖、只需 `swiftc`；CSS 做这种动画远比 AppKit 省事。不要改成 Electron 或 SwiftUI 重写。
- **浮层是非激活面板**（`NSPanel` + `.nonactivatingPanel`，重写 `canBecomeKey`），层级 `.popUpMenu`。理由：呼出菜单不抢走当前应用的焦点，但能收键盘事件。注意 `level` 必须在 `isFloatingPanel = true` 之后设置，否则会被重置成 floating。
- **全局热键用 Carbon `RegisterEventHotKey`**。理由：不需要辅助功能权限。
- **配置在每次呼出菜单时按 mtime 重新读取**，不用文件监听。理由：编辑器的原子保存会让 `DispatchSource` 监听失效，mtime 比较简单可靠。副作用：热键 / 手势的改动要到下一次呼出才生效（设置窗口保存时会主动重载，所以从设置窗口改是立即生效的）。
- **音效在 Swift 里合成并用 `AVAudioPlayer` 播放**，不用网页的 WebAudio。理由：原生播放可靠，且方便支持用户自定义音频文件覆盖。
- **不使用任何原作素材**。界面、图标重画，音效程序合成，仓库里没有动画的音频 / 图片 / 字体 / logo。用户曾要求「还原动漫里的声音」，处理方式是做一版风格接近的合成音并提供自定义音频文件的入口，而不是打包原声。开源后这一点更要保持。
- **动作在后台线程执行，且菜单最多等 0.5 秒就收起**。理由：修复「选 Downloads 时系统权限弹窗被全屏遮罩挡住点不到」的 bug —— 原因是主线程卡在等权限弹窗，菜单不关。不要把 `run()` 改回主线程同步执行。
- **`terminal` 动作用自删除的 `.command` 脚本实现**，而不是 AppleScript。理由：不需要「自动化」权限弹窗。脚本以 `#!/bin/zsh -i` 运行（别名和 PATH 可用），结尾 `exec $SHELL -l` 让窗口留在 shell。
- **触控板手势选「轻点」而非滑动**。理由：用户说系统自带的滑动 / 捏合手势他都在用，想不好选哪个；轻点不冲突。默认四指。实现只能用私有的 MultitouchSupport 框架（运行时 `dlopen`），macOS 没有读取全局触摸的公开 API。
- **鼠标手势默认「按住右键向下划」**（用户明确要求从左右键同按改成右键，并做成可配置）。右键模式下事件拦截器会扣住右键按下，判断是手势就吞掉，是普通点击就在松开时重放。代价：授权后右键菜单变成松开时弹出。没有辅助功能权限时退化为被动监听（能触发但会同时弹出右键菜单）。
- **设置窗口自动保存 + 打开时备份**（`~/.config/sao-menu/config.backup.json`），由 JS 用 `JSON.stringify` 生成文本再交给 Swift 写盘。理由：经 Swift 的字典序列化会打乱键顺序。
- **许可证 GPL-3.0**（用户选定，推荐过 MIT）。`LICENSE` 是从 gnu.org 下载的官方原文，不要手改。
- **release 由用户在 GitHub 网页上手动发布**。理由：本机没装 `gh`，agent 的终端拿不到 GitHub 凭据。
- **git 提交只在用户明确说 commit 时做**，每次一个提交；提交信息英文，结尾带 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`。

## 4. 踩过的坑与约束

- **agent 的终端里放不出任何声音**：连 `afplay` 播系统提示音都报 `AudioQueueStart failed`。从 agent 的 shell 直接执行 `build/SAOMenu.app/Contents/MacOS/SAOMenu` 启动的实例同样没声音。要让用户听到声音，必须用 `open build/SAOMenu.app` 启动（并且需要关闭沙箱执行）。直接跑二进制只适合看 `NSLog` 输出做冒烟测试，测完要 `pkill -x SAOMenu` 再用 `open` 重启。
- **agent 不能截屏、不能模拟键鼠**：`screencapture` 报无法创建图像；`osascript` 模拟按键会超时，还可能在用户屏幕上弹出「系统事件」授权框。不要再尝试。
- **界面验证方法**：把 `Resources/` 复制到临时目录，写一个注入了模拟数据的测试页，用无头 Chrome 截图（`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --screenshot=...`）。注意两个陷阱：`--virtual-time-budget` 下 CSS 过渡和动画会卡在起始帧，要看最终状态需在测试页里加 `*{animation:none!important;transition:none!important}`；`--timeout` 的实际截图时刻不可靠。画布动画（光束）只有实时模式能看到。
- **确认浮层窗口是否在屏幕上**：用一小段 Swift 调 `CGWindowListCopyWindowInfo`，按 owner 名包含 `SAO` 过滤（进程显示名是「SAO Menu」，带空格）。
- **临时签名导致辅助功能授权失效**：应用是 ad-hoc 签名，每次重新编译后系统视为新程序，「辅助功能」授权需要重新勾选。给用户新版本时要提醒。
- **传到别的 Mac 会被 Gatekeeper 拦**：没有公证，需要 `xattr -cr SAOMenu.app`。
- **触控板代码的风险点**：`Sources/main.swift` 的 `TrackpadTap.frame()` 假设每个触点记录 96 字节、归一化坐标在偏移 32 和 36。坐标超出合理范围时会放弃移动判断。如果用户反馈四指轻点没反应或四指滑动误触发，优先怀疑这里。无触控板时每 10 秒重试发现设备。
- **`isFloatingPanel` 会重置窗口层级**：见第 2 节，`panel.level` 必须放在它后面。
- **WKWebView 里文本框的 `⌘C` / `⌘V`** 依赖应用有主菜单，所以 `buildMainMenu()` 给这个无 Dock 图标的应用建了一个编辑菜单，不要删。
- **本机没有 `gh`，agent 推送会失败**：`git push` 在 agent 终端里报 `could not read Username`。需要推送或发 release 时，让用户自己执行（在提示符里输入 `! git push ...`），或让用户先 `brew install gh && gh auth login`。只读查询可以用公开 API：`curl https://api.github.com/repos/RiderLai/SAOMenu/releases`。
- **用 Python 脚本批量改文件后**，工具会提示文件在磁盘上被改动、需要重新 Read 才能用 Edit。会话里多数修改是用 `python3` 做字符串替换完成的（带 `assert old in s` 防止静默失败），这个做法可行。
- **用户的沟通习惯**：中文、指令很短（常常只有「git commit」「commit」）。需求有歧义时，我的做法是按最可能的理解都做掉并在回复里说明（例如「app 加一个 icon」同时做了应用自身图标和菜单里显示真实应用图标），用户没有反对过。
